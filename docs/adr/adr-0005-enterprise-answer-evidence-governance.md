# ADR-0005: 企业级问答来源、证据与权威裁决

- 状态：Accepted
- 日期：2026-09-21
- 协议：`turn-execution-plan.v3`、`run-source-manifest.v2`
- 关联：ADR-0001（LLM-Wiki 四平面）、ADR-0002（执行轨迹）、ADR-0003（科研证据）

## 背景

问答系统可以同时调用知识库、MCP、Skills、工具、子智能体、LLM-Wiki 和公共数据库。
如果只把这些能力作为提示词素材，模型可能扩大用户授权的来源范围、把导航内容误当证据、
在权威源未命中时凭记忆补写，或为不涉及原文的答案制造页码和原文引用。企业环境要求每个
最终结论都能回答：本轮允许用了什么、实际用了什么、权威源给出了什么裁决，以及引用是否
达到该结论所需的证据等级。

## 决策

### 1. 先冻结计划，再暴露能力

每轮在检索和工具暴露前生成 `TurnExecutionPlan`。计划冻结任务意图、来源策略、允许/禁止的
来源类型、能力要求、证据等级、引用策略和逐 Claim 义务。Skill 动态增加的工具仍须再次经过
计划过滤；工具、MCP、子智能体和模型不得自行放宽计划。

### 2. 来源分为 Authority、Expansion 与 Navigation

- Authority：本地文档、知识图谱、规范化数据记录、受信结构化数据库和题录源，可进入
  `EvidenceEnvelope` 并支持对应等级的结论。
- Expansion：公共数据库、MCP 或工具产生的候选事实，只有经过注册、审计且与 Claim 义务
  匹配时才能被采纳。
- Navigation：LLM-Wiki、摘要、思维导图和派生页面只负责导航、召回和解释结构，永不成为
  原始证据，满足 `WikiNavigationHit ∉ EvidenceEnvelope`。

未知知识产品默认 fail closed；新增产品必须先在 `knowledge/products/registry.py` 注册角色与
证据资格。

### 3. 证据采用 E0–E4 分级

| 等级 | 可支持内容 | 引用策略 |
| --- | --- | --- |
| E0 | 无外部事实义务的通用回答、变换和社交对话 | 不显示来源 |
| E1 | 规范化数据记录、数据库事实和字段来源 | 只显示数据版本/记录定位，不伪装成原文引用 |
| E2 | DOI、PMID、题名等书目信息 | 只显示题录引用 |
| E3 | 文档内容 Claim | 必须绑定已验证证据单元 |
| E4 | “原文/第几页/图表位置”等定位请求 | 必须绑定逐字原文与物理定位 |

只有 E3/E4 允许原文引用和 PDF 页码能力。没有涉及原文时，即使检索过文档，也不得输出
原文、页码或“查看证据”式暗示。`SOURCE-ONLY` 只有在指定来源真实命中并被采纳时才能发布。

### 4. 权威查询必须给出明确裁决

权威源的结果不是布尔值，而是 `HIT / MISS / UNAVAILABLE / AMBIGUOUS / CONFLICT`：

- HIT：只输出权威记录中的内容及可复核定位；
- MISS：闭世界范围内确认未收录，禁止调用模型记忆补定义；
- UNAVAILABLE：范围、版本、权限或服务不可用，不能冒充 MISS；
- AMBIGUOUS / CONFLICT：公开歧义或冲突，禁止替用户猜选。

词典查询采用精确词条/别名匹配、NFKC + case-fold 规范化，只读取已发布 ACTIVE release 的
冻结修订。存量明确的 CSV 词典通过版本化迁移晋升为 `glossary@1.0.0`，并生成不可变发布清单。

### 5. 运行清单是审计事实，不是模型自述

`RunSourceManifest` 记录计划来源、实际 `source_uses`、证据 ID、请求/结果摘要、来源版本、
采用状态、使用平面、验证结果与逐 Claim `authority_outcomes`。MCP 调用只从 append-only 调用
审计投影；知识检索只从冻结 Contract 投影。未实际调用或未被采用的来源不得进入答案来源。

子智能体必须返回 `subagent-evidence-bundle.v1`，包含子 run、冻结计划、知识范围、检索记录和
完整来源清单；父智能体只合并该结构化账本，不把子智能体自然语言自述当作证据。

### 6. 输出在发布前确定性门禁

最终文本在流式发布前缓冲并执行：证据等级门禁、引用绑定验证、词典确定性渲染、
`SOURCE-ONLY` 校验和禁用来源检查。失败时删除未授权引用或整轮 fail closed，并把原因写入
运行清单；不得让模型自行决定是否遵守。

## 验收标准

- 相同问题、范围快照和发布修订产生可复现的来源裁决；
- 权威 MISS/UNAVAILABLE 时答案不被模型常识“补全”；
- E0/E1/E2 答案没有原文、页码或 PDF 证据入口；
- LLM-Wiki、思维导图和未知产品不能进入证据通道；
- MCP、知识检索和子智能体都能从最终 Claim 回溯到运行审计与版本；
- Schema 变化通过版本化迁移，发布清单与规范化记录可在数据库中核验。

## 后果

系统会在来源不可用时更频繁地明确拒答或返回 MISS。这是有意的可靠性取舍：答案覆盖率让位
于来源边界、可复现性和审计完整性。未来新增 Web 或公共数据库 Provider 时，必须声明来源
类型、最高证据等级、信任登记和失败语义，不能仅通过新增工具绕过本 ADR。
