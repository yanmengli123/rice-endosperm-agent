## 本批接入说明

- 个人 MCP：管理员设置 `YUXI_PUBLIC_URL=https://服务域名`，在“设置 → 个人 MCP”配置服务商已注册的客户端、授权/令牌端点和 resource；将显示的回调地址登记给服务商。每位用户独立授权。配置保存会变更 revision，旧连接需重新授权。PKCE S256、浏览器 Cookie、一次性 state、授权 epoch 和资源 URL 共同绑定；令牌与 client secret 均走 AES-GCM。撤销立即阻止后续调用，不代表撤回服务商已执行的动作。
- 飞书：新增 `feishu` 类型，仅搜索指定空间的 Docx 文档。搜索返回标题候选，正文读取再次验证空间与节点类型；不把标题声明成已验证事实。用户 Token 加密落库，返回元数据使用“保持原值”标记；到期后由管理员更换，不自动刷新共享 Token。
- Milvus：新集合启用 `enable_match`。旧集合没有该字段时明确拒绝文本条件并保留原集合；完整短语要求服务器 >= 2.5.17。当前原服务的 2.5.6 未升级。迁移索引必须建独立集合、核对后切换，不能删除旧集合赌升级。
- Skills：包括旧文件创建、删除与依赖入口，全部通过不可变目录发布；根 frontmatter 与面板的依赖冲突明确拒绝。未保存时阻止切换文件，并在离开页面前保留用户选择。

## 协作消息与停止边界

0126 迁移新增协作消息和停止标记。消息只能发给同一用户、同一租户、同一运行树的成员；按调用 ID 幂等，单组限制消息数量和正文长度。在下一次模型边界读取，检查点保存已读 ID；读取后进程退出而尚未保存检查点时，会以相同消息 ID 重放。不会新增一轮独立模型调用，也不重写用量账本。

聊天侧栏的协作面板展示层级、状态、人工等待和消息送达，可发送引导或停止整组。工具提供 `subagent_tree`、`subagent_message` 和 `subagent_wait`。等待超时、部分完成和人工等待分别返回；失败/取消状态不会作为成功完成呈现。

派工、恢复与停止共享根运行的事务锁。并发名额在真正插入运行记录时复查；取消遍历所有后代，包含已完成中间节点下的活跃成员，不受 UI 的展示数量限制。原 `interrupted` 记录作为历史终态保留，停止标记阻止旧审批/恢复重新启动它。行锁读取强制刷新 ORM 缓存，防止迟到取消覆盖已经完成的状态。

实际验证：协作/原运行链/契约分组 107 passed；PostgreSQL 分组 7 passed，覆盖迁移重放与漂移、OAuth 并发刷新、并发派工、停止和插入竞争、迟到取消及旧等待点的恢复写入阻断。新增面板 ESLint 和 Vite 构建通过。真实模型、浏览器及成员人工审批全链路仍未验收。

部署前必须成套备份本分支数据库、MinIO、saves（含 Skills 包和版本目录）及主密钥；API/worker 使用同一重建镜像。APISIX 配置须在隔离环境重建验证。不得把官方 business/knowledge 基线迁移直接套在本分支，也不得删除新列/表来模拟回滚；应用和存储快照必须成套恢复。

## 多级委派与成员人工输入

管理员可配置协作深度 1–4 层（默认 1 层）及并发名额；根运行冻结这些限制，子成员仅能调用自己明确配置的下级白名单。配置校验和删除保护覆盖多级引用。普通用户保存其他配置时，保留管理员设置的限制且不能覆盖它们。

0127 迁移保存运行发出的原始问题、问题 ID、版本和消费记录。worker 在发布 interrupted 终态前保存等待点；保存失败明确失败，不发布可恢复的假状态。协作面板可打开成员问题，按原版本提交全部回答；同 request_id 重试返回原回执，不同回答冲突拒绝。停止、旧等待点、会话已推进和并发名额不足均阻止恢复。标记消费与恢复运行创建同事务提交。恢复保留子成员执行身份，任务树与子线程追踪到新的 run；恢复不增加委派深度。
