# 知识图谱索引任务可靠性修复

日期：2026-08-08

## 目标

修复 Milvus 知识库图谱索引任务在仍有待索引 Chunk 时被标记为成功的问题，并保证前端页面切换只停止当前视图的状态轮询，不影响后端任务执行。图谱抽取模型需要按已保存配置固化到任务参数，支持选择已启用的 `minimax-cn:MiniMax-M3` 聊天模型。

## 现象与原因

- 旧实现捕获单个 Chunk 的抽取、图数据库写入或图谱向量写入异常后，仅增加失败计数，最终仍正常返回；Tasker 因协程没有抛出异常而把任务标记为 `success`。
- 待索引查询每次只读取首批记录。一旦首批全部属于本轮失败项，循环会退出，后续待索引 Chunk 不再处理。
- 图谱状态接口只查活动任务或任意历史失败任务，没有稳定返回该知识库的最新任务；历史“成功但仍有待索引”的异常记录无法在页面上准确呈现。
- 页面切换会卸载图谱组件并停止局部轮询。后端任务实际独立运行，但旧的错误终态让用户返回页面后误以为任务被切页中断。

## 验收标准

- [x] 使用稳定游标遍历所有待索引 Chunk，前一批存在失败项时仍继续处理后续批次。
- [x] 对失败 Chunk 自动重试最多 3 次，并在每轮后重新读取权威待索引数量。
- [x] 只有权威待索引数量为 0 时任务才能进入 `success`；仍有待索引时任务进入 `failed` 并保留失败结果和错误原因。
- [x] 状态接口返回最新图谱任务；历史 `success + pending > 0` 状态按失败呈现。
- [x] 图谱任务参数保存所选聊天模型，并在整个任务中使用该模型快照。
- [x] 图谱配置拒绝不存在或非聊天类型的抽取模型。
- [x] 页面返回知识图谱后重新读取后台状态；组件停止轮询不会发送取消请求。
- [x] 索引管理面板展示抽取模型、待处理数量和失败原因。
- [x] 相关单元测试、接口测试、Lint、前端构建和本地页面切换验收通过。

## 模型职责边界

- `minimax-cn:MiniMax-M3` 用于从 Chunk 文本抽取实体和关系。
- 知识库的 Embedding 模型用于实体与三元组向量化；它不可由聊天模型替代。
- Re-Ranker 只参与查询结果重排，不参与图谱索引写入。
