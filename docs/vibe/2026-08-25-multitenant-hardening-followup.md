# 多租户 P0-P4 对抗性加固

## 背景

P0-P4 已建立凭据加密、租户身份、设备会话、BYOK、用量账本与 RLS 脚手架。本轮针对四阶段交付做运行态和并发边界复核，修复会造成错误健康状态、跨租户访问、会话重放、错误计费或平台凭据意外回退的确定性缺陷。

## 验收范围

- [ ] API 与 Worker 在未显式配置主密钥的开发环境共享同一持久化密钥；生产环境继续强制显式配置。
- [ ] 初始化脚本为既有和新建 `.env` 补齐 `YUXI_SECRET_MASTER_KEY`。
- [ ] API/Worker 并发启动时，版本化迁移只由一个进程执行。
- [ ] 被暂停或移除的租户成员不会在业务请求中被自动恢复；新用户只在显式开户流程中加入默认租户。
- [ ] 刷新令牌旋转锁定令牌行，访问令牌的 `sid` 必须属于当前用户。
- [ ] 冻结到 AgentRun 的 BYOK 凭据被删除、撤销或供应商不匹配时立即失败，并在任务结束后清理 ContextVar。
- [ ] 用量账本从 AgentRun 获取权威 uid/tenant_id，避免调用方伪造归属。
- [ ] 关键数据库与凭据解密初始化失败时服务启动失败，不再对外报告虚假健康。
- [ ] 补充回归测试，并通过相关单测、静态检查和容器启动冒烟。

## 非目标

- 桌面端 Stronghold/PKCE 多账号发布（P2b）。
- Neo4j、Milvus、MinIO 存量数据的租户重建（P4b）。
- 企业邀请审批、模拟登录与完整预留结算产品流程。
