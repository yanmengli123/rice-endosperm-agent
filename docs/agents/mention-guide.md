# @ 提及与唤醒使用规范

在聊天输入框中使用 `@` 可以提及（唤醒）具体资源：知识库、文献、MCP 服务器、Skill、子智能体与线程文件。本文说明 **什么时候该 @、@ 了会发生什么、哪些组合会被拒绝**，帮你把 @ 用成精确的控制器而不是运气开关。

## 核心心智模型：@ 是权限收窄契约，不是提示词

@ 不是"提醒模型看某个东西"的礼貌用语。一条 @ 提及在服务端经历四个不可绕过的阶段：

1. **互校**：前端发出的结构化 payload 与消息文本中的 token 必须一致，不一致整轮拒绝；
2. **重鉴权**：服务端重新验证你对每个资源的访问权，无权与不存在对外不可区分（防资源枚举）；
3. **冻结**：解析结论写入本次运行的快照，运行期间权限变化不会扩大本轮范围；
4. **后验**：运行结束时核对"点名的执行者是否真的被调用过"，未兑现会明确记录。

因此，**@ 的语义是"授权系统把本轮范围收窄到这里"**。收窄是单向的：@ 之后系统不会替你扩回去了。

## 三层唤醒决策：能不 @ 就不 @

| 层级 | 手段 | 语义 | 适用场景 |
| --- | --- | --- | --- |
| L0 隐式 | 不 @，自然语言提问 | 执行计划自动选源 | **默认选择**，绝大多数轮次 |
| L1 范围类 | `@doc` `@knowledge` `@page` `@figure` `@table` `@file` | 把**证据范围**收窄为检索硬约束 | 已知答案在哪篇文献/哪个库 |
| L2 执行者类 | `@mcp` `@skill` `@subagent` | 点名**执行者**，必须实调后验 | 结论必须来自指定来源/工作流 |

L2 是最强约束：点名 MCP 后本轮只允许该来源，且模型没有实际成功调用它时本轮会被降级披露。只在"这条结论必须来自 X"时使用 L2。

## 分类型使用规则

### @mcp（点名数据服务器）

1. **一轮只点一个服务器**。点名两个及以上时，单一服务器强绑定让位，系统按能力级来源策略处理（逐个服务器的"实际调用过"核验仍然生效，执行计划中会显式标注 `多重点名 MCP：未建立单一服务器强绑定`）。
2. **点名即绑定，等价不顶替**：点名了已启用的服务器，系统不会用"能力等价"的其他服务器替你代答；点名了**未启用**的服务器会直接拒答并明示（`MCP_SERVER_NOT_CONFIGURED`）。这是设计意图——先在扩展管理页确认服务器已启用。
3. **询问不算点名**：「BioMCP 是什么」这类了解性提问不会触发绑定。想了解用自然语言，想强制使用才 @。
4. **点了就要接受核验**：运行结束时若点名服务器没有被成功调用，本轮会被降级披露（`MENTION_MCP_NOT_INVOKED`），不会静默换源。不要 @ 完又问无关问题。

### @skill（技能预激活）

1. **默认不需要 @**。Skill 采用渐进披露：模型会自主读取并激活。@skill 的正确用途是**明确要求遵循某个输出契约**（例如"按 SOURCE-ONLY 数据模式给我结果"），此时该技能被确定性预激活，不依赖模型自觉。
2. **数据契约型 Skill 只在数据轮 @**。本轮执行计划禁用结构化数据库来源时（词典、文献、文档定位等轮次），依赖 MCP 的 Skill 会被策略性剔除（终态记 `SKILL_PLAN_DISPATCH_DROPPED`，与撤权区分）。要么不 @，要么在对应的数据轮 @。
3. 运行中 Skill 被撤权会立即失效（失败关闭），终态记 `SKILL_REVOKED_MIDRUN`。

### @subagent（委派白名单收窄）

1. 语义是**收窄**委派集合（"只允许委派给这几位专家"），而非强制调用；未被委派时终态披露（`MENTION_SUBAGENT_NOT_DELEGATED`）。
2. **前置条件：必须先在智能体配置里显式列出子智能体白名单**。未配置时 @subagent 一律拒绝（`SUBAGENT_UNAVAILABLE`）——这是刻意的失败关闭，防止 @ 默认放大委派面。
3. **执行者类提及不随子运行继承**：子智能体不会继承父轮的 @mcp/@skill/@subagent。要让子智能体使用某数据源，在**子智能体自己的配置**里绑定。

### 范围类（@doc / @knowledge / @page / @figure / @table / @file）

1. **@doc 优于 @knowledge**：越精确歧义越少；@knowledge 是交集收窄，只会缩小范围。
2. **@page / @figure / @table 必须依附唯一 @doc**：单独 @ 图或页会被判歧义整轮拒绝（无论强度，均不受豁免）。正例：`@doc:xxx @figure:图3`。
3. **@file 是最弱的绑定语义**（文本路径绑定），高敏感场景优先用 @doc。
4. **从输入框 @ 弹层选择，不要手打 token**：手打按精确名匹配，重名直接拒绝且无模糊纠错。

### @tool：不支持

工具不暴露给用户点名（工具可见性由执行计划与 Skill 依赖门控控制）。前端弹层也没有工具分组，请勿宣传该用法。

## 组合冲突速查

| 组合 | 实际结果 | 建议 |
| --- | --- | --- |
| @mcp +「用知识库回答」 | 显式来源约束以 MCP 为准，知识库被禁 | 不要在同一条消息里给矛盾指令 |
| @mcp ×2 | 丢失单一强绑定（已显式标注），逐个仍后验 | 一轮一个服务器 |
| @mcp +「不要用 MCP」 | 点名已冻结，必然记未兑现 | 禁止自相矛盾 |
| @doc + @knowledge（文献不在该库） | 范围冲突整轮拒绝 | 选择前确认归属 |
| @figure 无唯一 @doc | 歧义整轮拒绝 | 必须带唯一父文献 |
| 单轮超过 32 条提及 | 鉴权前整轮拒绝 | 拆多轮，或只用 @knowledge |
| @mcp 未启用 | 拒答并明示 | 先在扩展管理启用 |
| @subagent 未在配置列出 | 拒答 | 先配置子智能体白名单 |

## 管理员治理清单

- **MCP 上架三件套**：能力注册（决定计划过滤与可答性）、接入每日 canary 期望集、绑定决策记录（哪个智能体、为什么）。
- **Skill 依赖声明必须完整**：依赖声明同时驱动"计划分派剔除"和"工具门控"两道闸，漏声明等于两道闸同时失效。
- **子智能体白名单**：新建子智能体时显式配置知识范围与受众；@subagent 依赖智能体配置中的显式白名单。
- **观测**：每次运行结束会发射「提及兑现汇总」轨迹事件（`run.mentions.finalized`，按 mcp/skill/subagent 分类统计兑现数）。"点名兑现率"（兑现数/点名轮次）是 @ 体系健康度的单一最佳指标，也能发现"用户总在 @ 未启用的服务器"这类培训信号。
